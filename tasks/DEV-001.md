# DEV-001: init.md ↔ init-project.md 구조 정합성 개선

> **등록일**: 2026-05-28
> **출처**: v0.3.5 전체 감사 W2 항목
> **상태**: ✅ 완료 (v0.4.0) — `/init` + `/init-project` → `/kickoff` 단일 통합으로 해소

## 배경

v0.3.0에서 `/init`이 재설계되면서 레거시 `/init-project`와 구조적 괴리 발생. 기능 결과는 동일하나 내부 구조가 다름.

## 차이 목록

| 항목 | init.md (v0.3.0+) | init-project.md (레거시) |
|---|---|---|
| 질문 번호 | Q0-Q4 (5개, 통합) | Q0-Q6 (7개, 분리) |
| Always-copy RULES | 4개 (TERMINOLOGY, REFACTORING, VERSIONING, PROJECT_LIFECYCLE) | 4개 (v0.3.5에서 수정 완료) |
| 스캐폴딩 범위 | .claudeignore, .claude/commands/, docs/ 7폴더, apps/ | INDEX.md + .gitignore만 |
| 백로그 파일명 | TASK.md + tasks/DEV-XXX.md (영문) | 개발예정사항.md + 개발예정사항_상세/ (한국어) |
| 완료 리포트 | 제네릭 + 플러그인 추천 | 3블록 상세 (Firebase/SEO+GEO 체크리스트) |

## 작업 방향

- init-project.md는 하위호환 레거시이므로 init.md 수준으로 끌어올리는 것은 과잉
- 대안: init-project.md 상단에 "이 커맨드는 /init의 레거시 버전입니다. 새 프로젝트는 /init 사용 권장" 안내 강화
- 또는: init-project.md를 단순 redirect로 변경 (init.md 실행 위임)

## 우선순위

낮음 — 기능상 문제 없음. init-project.md 사용자가 거의 없을 것으로 예상.
